# 講義與審查指南

## 講義：每個單元的固定結構

1. **這一課要做什麼**：做完會得到哪些數字、時數分配（例如「讀 2 h／寫程式 4 h／練習 2 h」）。
2. **需要的物理／數學**：推導每一步都寫出來，不跳步；慣例（時間慣例、正負號）在開頭說清楚。
3. **一步一步寫程式**：每一步＝完整程式碼＋逐行解釋＋執行指令＋**實際輸出**（從終端機貼上，不手打）。
4. **我們踩過的坑**：把真實的錯誤版本也做成可重現的程式和數字。
5. **常見錯誤表**：症狀 → 原因 → 修法。
6. **練習與完整解答**：需要跑程式的練習也要實際跑過；太耗時的明確標示。
7. **自我檢查**：checkbox。

另外：
- 第 0 單元補前置工具（切片、差分、複數、傅立葉、單位），學習者起點以下的東西都要補。
- `code/` 一支程式只做一件事，可單獨執行；Windows 下用 `PYTHONUTF8=1` 避免 `UnicodeEncodeError`。
- 外部程式（CUDA 等）要實際編譯執行；批次檔只用 ASCII。
- 課程總覽：起點、終點、逐週對照表（週、主題、時數、課、範例程式）、和舊版的差別、和進度表的差異、本機環境。

## 五位審查：分工

同一則訊息平行派出（`general-purpose`，預設模型），每位只看自己的面向，報告寫到 `reviews/審查N_*.md`，結尾給「錯誤／必須修／建議」三級清單：

| # | 專責 | 要做的事 |
|---|---|---|
| 1 | 數字與輸出 | 重跑 `code/` 每支程式，逐字比對講義中的輸出與內文數字 |
| 2 | 物理與推導 | 逐步驗算推導、正負號、慣例；不能只看結論 |
| 3 | 程式正確性 | 讀程式找數值方法錯誤、邊界錯誤、參考解是否乾淨 |
| 4 | 教學設計 | 以「只會 Python 的初學者」身分試讀：哪裡會跑不動、算錯、看不懂 |
| 5 | 進度表／引用／一致性 | 時數、題號、課本章節版本、跨單元數字一致、路徑正確 |

brief 要寫清楚：資料夾路徑、學習者起點、只審不改（審查者不得修改講義）、報告格式。

## 修正與第二輪

1. 彙整成 `reviews/講義檢查紀錄.md`：第一輪結論表（審查、專責、結論、錯誤數）→ 依單元列出修正（標註來源，例如「審查 2 錯誤 3」「M8」）。
2. 「練習沒做」類的意見，優先實際做出來（新程式＋實測數字），不要只改措辭。
3. 用 SendMessage 把修正清單送回**同一批**審查做第二輪；表格記錄「通過／第二輪新發現並已修正」。
4. 全部通過才寫腳本。
